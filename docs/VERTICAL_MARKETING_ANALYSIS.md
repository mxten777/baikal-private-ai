## 1. 결론 요약

> **전략 방향은 맞다. 하지만 실행 경로에 치명적 약점이 3개 있다.**

- 폐쇄망 + HWP + 법령 조합으로 **공공기관 법령 버티컬에서는 경쟁력이 있다**
- 계약서 AI로 민간 법무팀을 첫 고객으로 삼는 전략은 실행 경로와 리스크 관리가 명확하지 않으면 **6개월을 낭비할 수 있다**
- 지금 당장 해야 할 한 가지는 버티컬 기술 개발보다 앞서 **"PoC를 허락해줄 기관 한 곳"을 찾는 것**이 전략 전체의 병목이다

---

## 2. 진짜로 작동하는 강점

### 폐쇄망 × 버티컬의 궁합

이 전략에서 가장 강력한 부분이다.

- 계약서/법령 문서는 외부 유출 통제가 가장 엄격한 문서
- 폐쇄망 + 버티컬 특화를 동시에 충족하는 제품은 국내에 드물다
- ChatGPT/Claude로 계약서 원문을 분석하는 기업 법무팀은 사실상 없다 → **수요가 실재하는 시장**

### HWP 지원의 실질적 차별화

- 공공기관·법무법인 기준 계약서/규정 원본이 HWP인 경우가 지금도 흔하다
- 대부분의 외산 RAG 솔루션이 여기서 막힌다
- 단순 기술 특징이 아닌 **실제 영업 포인트**로 작동한다

---

## 3. 치명적 약점 3가지

### 3-1. 계약서 버티컬 — 할루시네이션 리스크가 버티컬 선택 자체를 위협한다

가장 큰 문제다.

법무팀이 "손해배상 한도 조항 찾아줘"라고 물었는데 AI가 **틀린 조항을 틀린 내용으로 제시**하면?

| 문제 | 설명 |
|------|------|
| 모델 한계 | qwen2.5:7b 로컬 모델 기준 계약서 법률 용어 해석 정확도 보장 어려움 |
| 용도 혼동 | BAIKAL은 "검색"이지만 고객은 "검토"로 사용할 가능성 있음 |
| 책임 구조 | 법적 오류 발생 시 공급자 책임 범위 불명확 |
| 심리적 저항 | 법무팀은 이 리스크를 이미 알고 있어 도입 결정을 매우 조심스럽게 함 |

> **결론**: 계약서 버티컬 1순위 판단은 재검토가 필요하다. ROI 설명이 쉬운 만큼 **실수의 비용도 크다**.

---

### 3-2. "법무팀이 독립 예산 집행"이라는 전제가 틀렸다

전략 문서의 핵심 전제:
> *"법무팀/구매팀은 독립 예산 집행 권한 보유 — IT팀 승인 불필요"*

이 전제는 **대기업 일부에만 해당하는 예외적 케이스**다.

| 기업 규모 | 실제 구매 경로 |
|-----------|----------------|
| 대기업 | 법무팀 → IT 보안팀 → 구매팀 → 계약 (6~9개월) |
| 중견기업 | 법무팀 건의 → 경영진 → IT → 구매 (3~6개월) |
| 스타트업 | CEO 직접 결정 (빠르지만 예산이 작다) |
| 법무법인 | 파트너 동의 없이 IT 인프라 도입 불가 |

전략 문서의 "영업 사이클 1~3개월"은 **현장 기준으로 낙관적**이다.

---

### 3-3. 첫 앵커 고객 확보 경로가 없다

전략 문서 어디에도 **"어떻게 첫 고객을 만날 것인가"** 가 없다.

- 법무팀은 콜드 영업에 반응하지 않는다
- 계약서 AI 시연 자료를 들고 법무팀 미팅을 성사시킬 네트워크가 있는가?
- 레퍼런스 없이 계약서·법령을 다루는 기관에서 PoC 기회를 주지 않는다
- **"레퍼런스가 없어서 첫 고객을 못 잡고, 첫 고객이 없어서 레퍼런스가 없는" 구조**

## 4. 버티컬 순위 재평가

| 버티컬 | 전략서 순위 | 냉정한 재평가 | 이유 |
|--------|-------------|---------------|------|
| 계약서·법무 | 1순위 | **3순위** | 할루시네이션 리스크 × 법적 책임 × 영업 경로 부재 |
| 법령·조례 | 2순위 | **1순위** | 공공 조달 경로 존재, 정답 검증 가능, HWP 강점 직결 |
| 견적서·품의서 | 3순위 | **2순위** | ERP 없이도 독립적 가치, 숫자 정답/오답 명확 |

### 법령 버티컬을 1순위로 올려야 하는 이유

1. **검증 가능성**: "제17조 제2항"이라는 답은 맞고 틀림이 명확 → 할루시네이션 검증 가능
2. **진입 경로**: 공공 조달(나라장터, 정보화전략계획)은 레퍼런스 없이 입찰 가능한 경우 존재
3. **복사 영업**: 지자체 한 곳 시범사업 성사 시 유사 지자체 복사 영업 가능
4. **HWP 직결**: 공공기관 HWP 의존도가 민간보다 훨씬 높아 BAIKAL의 HWP 지원이 직접 차별화

## 5. 진짜 위험 요소

### 경쟁사가 이미 움직이고 있다

- 국내 AI 스타트업 중 계약서 AI를 명시적으로 하는 곳들이 2025~2026년 사이 등장했다
- 삼성SDS, SK C&C 같은 SI 업체들도 폐쇄망 RAG 구축 사업을 수주 중이다
- **2~3주 개발 격차는 경쟁 우위가 아니다**

### 기술이 아니라 영업이 병목이다

- 개발 1인 기준이라면 버티컬 MVP 개발 2~3주 후 영업에 집중할 수 있는 시간과 채널이 있는가?
- 기술 완성도를 높여도 **영업 채널이 없으면 시장경쟁력은 없다**
- 제품이 준비된 것과 시장이 반응하는 것은 다른 문제다

## 6. 시장경쟁력 최종 판정

| 항목 | 판정 | 비고 |
|------|------|------|
| 전략 방향성 | ✅ 맞다 | 버티컬 전환 자체는 올바른 판단 |
| 버티컬 순위 (현재) | ⚠️ 재검토 필요 | 계약서 1순위는 리스크 과소평가 |
| 기술 기반 | ✅ 실작동 제품 있음 | 파일럿 납품 가능한 수준 |
| 폐쇄망 차별화 | ✅ 진짜 차별화 | 외산 솔루션과 실질적 분리 |
| 첫 고객 확보 경로 | ❌ 전략에 없음 | **치명적 공백** |
| 할루시네이션 리스크 관리 | ❌ 계획 없음 | 계약서 버티컬 진출 시 필수 |
| 가격 경쟁력 (SaaS) | ⚠️ 높은 편 | 국내 중견기업 기준 부담 가능성 |
| 1인 실행 가능성 | ⚠️ 제한적 | 개발은 가능, 영업은 별도 자원 필요 |

### 최종 판단

> **공공기관 법령 버티컬에서는 시장경쟁력이 있다.**
> 폐쇄망 + HWP + 법령 조합은 국내 시장에서 실제로 빈 자리다.
>
> **그러나 지금 당장 계약서 AI 민간 법무팀 영업을 시작하면 6개월을 낭비할 수 있다.**
> 기술이 아니라 "PoC를 허락해줄 기관 한 곳"을 찾는 것이 전략 전체의 병목이다.

## 7. 기술 충분함을 어필하는 방법

**기술은 이미 충분하다. 문제는 그것을 증명하는 자료가 없다는 것이다.**

### 7-1. 수치로 말한다 — RAG 평가 지표 공개

`scripts/eval_rag.py`가 이미 구현되어 있다. Precision@K, Recall@K, MRR, nDCG@K, Reranking Lift를 자동 산출한다.

```powershell
python scripts/eval_rag.py --testset scripts/eval_testset.json --k 5 --mode hybrid
```

이 결과를 제안서 첫 페이지에 넣는다:

| 지표 | 측정값 | 의미 |
|------|--------|------|
| Precision@5 | (측정) | 상위 5개 중 관련 문서 비율 |
| Reranking Lift | (측정) | Cross-encoder 적용 전후 정확도 향상폭 |
| 평균 응답 지연 | (측정) | CPU 환경 기준 |

> 경쟁사는 이 수치를 공개하지 않는다. **숫자가 있다는 것 자체가 차별화다.**

---

### 7-2. 같은 문서로 비교 시연한다

고객의 HWP 파일 하나를 ChatGPT와 BAIKAL에 동시에 올려 같은 질문을 던진다.

| 항목 | ChatGPT / Claude | BAIKAL |
|------|:---:|:---:|
| HWP 원본 업로드 | ❌ 불가 | ✅ |
| 인터넷 차단 환경 | ❌ 불가 | ✅ |
| 출처(조항/페이지) 표시 | ❌ 없음 | ✅ |
| 데이터 외부 전송 | ❌ 전송됨 | ✅ 없음 |

**이 4줄이 어떤 기술 설명보다 강하다.** 기술 용어 없이도 담당자가 이해한다.

### 7-3. 검증된 외부 모델 기반임을 솔직하게 강조한다

"우리가 만든 AI"가 아니라는 점을 솔직히 말하는 것이 오히려 신뢰를 얻는다.

### 8-2. "RAG 전문 비교 사이트"는 없다 — 이것이 오히려 기회다

**솔직한 현황**: 2026년 현재 "폐쇄망 RAG 솔루션만 전문으로 비교하는 중립 사이트"는 존재하지 않는다.
G2·Capterra에도 국내 폐쇄망 RAG 카테고리 자체가 없다.

→ **BAIKAL이 직접 비교 콘텐츠를 만들면 이 분야 검색 상위를 선점할 수 있다.**

```
기술 비교 블로그 작성
("BAIKAL vs Dify — HWP 문서 처리 실전 비교")
        ↓
네이버 블로그 / 개발자 커뮤니티 공유
        ↓
구글/네이버 검색 "폐쇄망 RAG 비교" 상위 노출
        ↓
PoC 문의 인바운드 발생
```

**콘텐츠 작성 원칙**: "우리가 제일 잘 한다"가 아니라 "같은 조건에서 어떻게 다른지"를 객관적으로 서술한다. 약점도 솔직히 쓰는 것이 기술 독자에게 신뢰를 얻는다.
